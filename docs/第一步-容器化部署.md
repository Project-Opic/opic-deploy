## 一、部署形态与目录

容器化模式 = 8 项基础设施全部以容器交付（数据面 Pigsty 形态见 116 号 §三决策 1，用于生产；本模式用于 DEV 与 minimal 档）：

```
宿主 192.168.3.200
├── 统一入口  opic-traefik        :18880(web) :19443(websecure) :18887(dashboard)
├── 数据面    opic-pg (16)        127.0.0.1:15432（回环排障口，容器网 opic-net 内 5432）
│             opic-redis (8)      127.0.0.1:26379（同上）
├── 身份面    opic-zitadel        经网关 auth.192.168.3.200.nip.io:18880
│             opic-zitadel-login  （login 前端，仅容器网内 :3000）
│             opic-casdoor        :18001
├── 中间件    opic-nats           :14222(client) :8222(monitor)
│             opic-temporal(+pg+ui) :7233(gRPC) :8233(UI)
└── 镜像仓    harbor(安装器自管)   :18700
```

- 所有栈通过外部 Docker 网络 `opic-net` 互联；数据目录统一在 `/opt/opic/`。
- 部署根目录：`/opt/opic-deploy-step1`（独立于既有 `/opt/opic-deploy` 域中心目录）。
- **端口规划依据**：宿主 80/443 被系统 nginx 占用、8080 被 kube-router 占用、8000/4222/5432/16379/18090-18115/18443/8880-8881/8086 被既有容器（go-admin-kit、zt-traefik、oc-redis 等）占用 → 全部让开。

## 二、快速开始（3 条命令）

```bash
cd /opt/opic-deploy-step1
bash bin/install-step1.sh                 # F0~F8 全量（含 Harbor）
bash bin/install-step1.sh --no-registry   # 跳过 Harbor（离线拿不到安装包时）
bash bin/verify-step1.sh                  # 八项健康门禁（可随时重跑）
```

`install-step1.sh` 幂等可重跑：已存在的 `.env` 不会被覆盖，已健康的栈会秒过。

## 四、配置源（.env 要点）

- 唯一配置源是 `.env`（从 `.env.example` 生成），**口令只存在于该文件**；`configs/` 下无任何口令。
- **ZITADEL_DOMAIN 与 ZITADEL_EXTERNALPORT 必须与浏览器地址栏一致**（OIDC issuer 由它构成）。DEV 用 `auth.192.168.3.200.nip.io:18880`（nip.io 泛解析到 192.168.3.200）；若内网无外网 DNS，在各访问机的 `/etc/hosts` 加 `192.168.3.200 auth.192.168.3.200.nip.io`。
- **口令复杂度**：ZITADEL/Harbor 校验口令策略（大写+小写+数字+符号），`gen-env.sh` 生成 `Op1-` 前缀格式自动合规；手工填入口令时须自行满足。
- **镜像源**：ZITADEL 官方镜像在 ghcr.io 且 **tag 带 `v` 前缀**（`ghcr.io/zitadel/zitadel:v4.19.3`），docker hub 无 v 前缀且部分国内 mirror 不收录——DEV `.env` 已指向 ghcr。Casdoor 无可核验版本 tag 源，默认 `latest`，首装后建议回填锁定。

## 六、首次部署实测记录与已知坑

2026-10-01 在 192.168.3.200 实测过程中发现并已修复/规避的问题（新环境部署遇到同类症状可直接对号入座）：

1. **compose healthcheck 不支持 `environment` 键**：Redis 栈最初把 `REDISCLI_AUTH` 写在 healthcheck 内 → `additional properties 'environment' not allowed`。已改为 service 级 `environment` + healthcheck 里 `redis-cli ping`。
2. **空端口变量会绑随机端口**：`"${REDIS_PORT:-}:6379"` 在变量为空时绑定随机宿主端口。已改为固定回环默认值（如 `127.0.0.1:26379:6379`）。
3. **宿主端口冲突**：16379 被既有 `oc-redis` 占用 → Redis 换 26379；80/443/8080/8000/4222/5432 均被占用 → 全部高位让开（见 §一端口表）。
4. **共享 docker.sock 的发现污染**：宿主上 go-admin-kit 等容器自带 traefik labels，会被新 Traefik 收编 → 加 `--providers.docker.constraints=LabelRegex(\`opic.stack\`,\`.+\`)`，只发现带 `opic.stack` 标签的 OPIC 容器。
5. **traefik healthcheck 404**：scratch 镜像无 curl/wget，`traefik healthcheck` 需显式传入口点与地址：`--ping=true --ping.entrypoint=web --entrypoints.web.address=:80`。
6. **ZITADEL 镜像源**：docker hub 镜像在部分国内 mirror 不在白名单 → 用 ghcr.io（tag 带 `v` 前缀）。
7. **ZITADEL 口令复杂度**：首实例初始化会校验 admin 口令复杂度（`PasswordComplexityPolicy.HasUpper`），纯小写 hex 口令导致 setup 失败 → 口令生成改为 `Op1-` 前缀格式。
8. **ZITADEL healthcheck 死锁**：traefik 会过滤非 healthy 容器，而 `zitadel ready` 拨测经网关的外部域名 → 路由不注册 ↔ 不 healthy 互等。栈内**刻意不设 healthcheck**，就绪判定由 post-install 网关门禁承担。
9. **bootstrap 卷属主**：Docker 命名卷默认 root，zitadel（uid 1000）写 login-client PAT 报 permission denied → 栈内加一次性 `init-perms` 容器 chown。
10. **跨容器 traefik label**：Traefik 的 service 只指向 label 所在容器 —— login 路由必须挂在 login 容器上（挂 API 容器上会 502）。
11. **Casdoor 双坑**：`dbName` 只从 `conf/app.conf` 读（env DSN 只管连接），缺了报 `zero-length delimited identifier`；`--createDatabase=true` 需 CREATEDB 权限，库已由 database 栈建好时不带该参数。
12. **NATS `max_streams`**：不接受服务器级配置（2.14 报 unknown field），属账号级限额。
13. **Temporal 版本天花板**：`temporalio/auto-setup` 上游最高 1.29.x（docker-compose 仓已归档，无 1.30+ 镜像），全仓统一 1.29.0；镜像在受限网络可经任一可出网机器 `docker save` → `scp` → `docker load` 迁移。admin-tools 无 1.29.0，用 1.30.4（向后兼容）。
14. **跨架构镜像搬运**：从 Apple Silicon 机器 `docker save` 导出的默认是 arm64 变体，搬到 x86 宿主容器起不来（仅日志一行 platform mismatch）→ 导出前必须 `docker pull --platform linux/amd64`。

## 七、与生产形态（Pigsty）的切换

容器化模式是 minimal/DEV 形态。切生产时（116 号 §三决策 1）：

1. 数据面改由 Pigsty 主机级安装（PG HA + Redis 模块），`stacks/database`、`stacks/redis` 停用；
2. ZITADEL/Casdoor/Temporal 的数据库连接指向 Pigsty 实例（改 `.env` 的 host/端口与 SSL 模式）；
3. Traefik 关闭 `api.insecure`，启用 TLS（证书由 O-CRT 域供给）；
4. Temporal 库并入 Pigsty 统一实例（`temporal`/`temporal_visibility` 由 Pigsty 建库授权）。
